# v1.3.7 — 抖音自动回退与采集规则同步

相对 **v1.3.6** 的迭代，发布检查日期：2026-10-15。

## 1. 抖音下载失败自动进入播放页回退

- v1.3.6 的播放页捕获需要额外调用；v1.3.7 在每日 `prepare_douyin_ingestion.py` 中接入回退。下载接口返回403、缺少元数据或未取得播放媒体时，同次尝试使用已授权专用浏览器打开正常播放页。
- 下载、播放页回退和ASR共用一次尝试，不在API失败时提前耗掉冷却/次数。新作品和历史重试共享每来源每轮最多3条；新增按运行ID持久化的额度账本，同轮重复记录只更新结果、不重复计次。继续遵守6小时冷却和自动最多5次。
- 历史失败/截断ASR在下载前备份，避免旧缓存使下载器错误跳过本次处理；只有取得媒体后才运行ASR，验证失败保留具体原因并继续其他来源。

## 2. 精确识别当前播放器媒体

- v1.3.6 主要接受原生media请求；更新后支持 `blob:` / MediaSource 播放，以及fetch流式音视频读取。
- 追踪响应字节经读取、复制到 `SourceBuffer.appendBuffer` 的实际归属，只选择当前可见播放器确实接收的媒体；优先音轨，排除未进入播放器的预加载响应。不同清晰度或CDN地址不再仅因链接数量而报歧义。
- 在当前页面通过正常fetch读取新鲜媒体响应，下载前核实作品ID、作者和权限，下载后验证完整响应体、音轨及实际时长；不依靠时长相同猜测作品归属。
- 增加安全诊断：登录要求、验证码、播放器/标题/时长缺失、媒体归属不明、响应体及音轨错误分别记录；诊断和新观察审计不保存签名媒体地址或请求凭据。
- 真实公开播放页验证已取得1,991,223字节完整音轨：页面303.624秒，媒体303.623秒，含1条音轨、无视频轨。该验证未重做已完成正文或更改最终库。

## 3. 群聊、Discord及访问策略

- 群聊撤回消息提示按系统事件排除，即使DOM继承管理员角色也不会当作观点入库；同时断开角色/语音组继承。
- Discord回复深链限定原消息行后再读取内容和作者，修复重复DOM ID造成的严格模式异常，并避免误取其他消息的引用预览。
- 集中排除策略新增用户明确移除的失效作品和无口播作品，发现、重试、完成检查及事务入口共享，防止旧快照或待审文件重新导入。原订阅重复项排除规则保留。
- 微信财经文章显式白名单增加3个已授权链接的段落区间，仍只处理用户提供的链接，不扩大自动采集范围。
