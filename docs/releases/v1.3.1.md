# v1.3.1 — Incremental processing ledger and group capture hardening

Compared with `v1.3.0`, this release moves duplicate detection ahead of expensive enrichment work and hardens the scheduled Douyin group workflow.

## Processing reuse across channels

- Adds a read-only scheduler-state lookup that adapters can use before downloading or enriching an already processed item.
- X reuses byte-validated local static images when the tweet ID and source text are unchanged.
- Discord reuses byte-validated local static images when the message body and parent message ID are unchanged, while still refreshing exported payloads, expiring attachment URLs, and reply context.
- Douyin profile preparation checks both scheduler state and the final database. The two-hour discovery overlap remains, but only unseen public aweme IDs are sent to the downloader and Whisper.
- Substack caches article bodies by canonical URL/article ID and platform edit marker; unchanged articles no longer require a second full-page read.

## Douyin group reliability

- Adds a required per-run capture receipt bound to `QUANT_RUN_ID`, capture age, built-file hash, latest-end coverage, overlap coverage, and zero pending voice segments.
- Adds a cross-run group voice ledger. Because the page has no durable message IDs, it fingerprints a batch from verified role/avatar identity, resolved time separator, and ordered voice-duration sequence—not temporary DOM indexes or transcript text.
- Reuses a reviewed group transcript only when the fingerprint matches and its final database item still exists. Native “转文字” is required only for unknown segments.
- Keeps group failure isolated so X, Discord, Substack, and profile sources can complete when the group browser session is unavailable.
- Continues to exclude system notices and ordinary members, preserve group-owner/admin role boundaries, and require observed URLs for video-share cards.

## Ingestion and reporting fixes

- Accepts a scheduler summary emitted alongside a non-zero process result, allowing partial-source results to be reported and imported safely instead of being discarded wholesale.
- Preserves the transactional `ingestion_service.import_jsonl` guard and reports actual retained inserts separately from scheduler candidates.
- Adds the latest user-supplied 财躺平 article mapping without enabling unsolicited WeChat crawling.

## Verification

- Added regression coverage for group receipt replay rejection, group fingerprint stability, final-database existence checks, and X/Discord media reuse.
- Existing Discord cross-source guard, incremental review, and Panyi policy tests remain green.
- Python compilation, SQLite integrity, and diff-format checks pass.

Runtime databases, browser sessions, collected content, credentials, and one-time local repair scripts are not included in the release.
