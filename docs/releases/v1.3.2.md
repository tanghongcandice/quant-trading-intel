# v1.3.2 — Final-store recovery and public X long-post hydration

Compared with `v1.3.1`, this release makes final database commits authoritative for incremental processing and completes public X long posts from their detail pages.

## Final-store authority and recovery

- Uses `data/quant_intel.sqlite`—not scheduler capture state—as the authoritative source for deduplication, processing reuse, and cursor cutoffs.
- Re-emits an item as recoverable when scheduler state contains its stable ID but the final database does not. Recovery is recorded with `recovered_from_uncommitted_state=true`.
- Prevents an uncommitted scheduler cursor from excluding items in later runs; the two-hour overlap now starts from the cursor committed by the final import transaction.
- Restricts Douyin pre-enrichment reuse to aweme IDs present in the final database, so state-only records cannot suppress audio download or Whisper recovery.
- Adds regression coverage for final-store item and cursor authority.

## Public X long-post completion

- Detects non-subscription timeline cards with an explicit “Show more/显示更多” cue or a near-280-character unfinished ending.
- Reopens suspected public long posts in a reusable detail tab, waits for rendering to stabilize, and keeps the longest matching body.
- Keeps subscription-preview detection evidence-based and separate from public-source truncation.
- Adds regression coverage for progressively rendered detail text and hydration metadata.

## Data recovery performed with this release

- Recovered seven 久韭究财 works that had reached scheduler state without reaching the final database: four reviewed public transcripts and three member-only title records.
- Advanced the final-store cursor to the latest recovered aweme only after transactional import.
- Corrected the previously truncated public Edgerunner X post after confirming its complete detail-page body.

## Verification

- Processing-ledger, X long-post, subscription-policy, and group run-gate tests pass.
- Python compilation, `git diff --check`, SQLite integrity, FTS refresh, and local API visibility checks pass.

Runtime databases, browser sessions, collected content, credentials, recovery artifacts, and one-time local repair scripts are not included in the release.
