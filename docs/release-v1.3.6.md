# v1.3.6 — 近期群聊采集与浏览器网络复用

相对 **v1.3.5** 的代码更新，发布检查日期：2026-09-19。

## 1. 群聊近期回看模式

- 独立持久化 Playwright 群聊采集器完成授权启用，支持经验证的部分收据；完整历史覆盖不足时仍可导入已核实的新消息，同时冻结完整游标。
- 群聊入口等待动态群名和消息 DOM 稳定后再保存首个窗口，避免页面 shell、临时作者头和时间头导致误判。
- 失败轮保存 URL、标题和截图；已有同轮断点时返回最新端复核，而不是重新跑完整采集预算。
- 用户确认网页长期只能显示近期消息。到达页面最早边界且滚动无进展后有界停止，继续采集新消息但不清除未核实连续区间，也不把平台限制误报为转写或登录失败。
- 增加基于窗口哈希、带日期文字锚点和最终库正文的重试别名销账；不按语音时长猜测匹配。

## 2. 抖音公开播放页与访问策略

- 新增正常播放页媒体响应捕获，验证作者、访问标签、媒体主机、响应体大小和完整范围后才进入转录；`blob:` 地址不再直接等同于无音轨。
- 浏览器播放音频进入 ASR 前核对实际媒体时长；ASR 尾端超过媒体时长必须显式全文复核，不能自动标记完成。
- 对用户确认的久韭究财订阅重复作品实行集中排除，覆盖发现、重试、完成检查和事务入库，保留正确订阅记录。
- 支持经哈希验证的旧群聊断点恢复与审计，同时保留一次性历史修复工具在发布范围之外。

## 3. Substack 浏览器网络复用

- 归档 API 从 Playwright 独立 `APIRequestContext` 改为已加载页面中的同源 `fetch()`，复用浏览器实际可用的登录、DNS、代理和网络路径。
- 页面请求增加三次有界重试，明确报告 HTTP、无效 JSON 和重试耗尽；失败不推进最终数据库游标。
- 在线验证中，持久化 profile 打开归档页返回 HTTP 200，页面内 API 成功返回归档数据。

## 4. 其他采集修正

- 新增一篇用户提供的微信公众号财经文章段落配置，仍按显式链接白名单处理，不扩大公众号采集范围。
- 修正每日入口调用群聊诊断工具的参数顺序，确保同轮部分收据完成后执行真实校验。
- 完成检查、重试选择、候选发现和最终事务入库共享同一抖音访问排除策略，避免被确认的订阅重复项从旧待审文件重新进入数据库。
